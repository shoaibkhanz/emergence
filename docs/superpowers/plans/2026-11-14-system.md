# System (status bar) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CPU, memory, disk and (on battery) battery in the status bar's right side, each opening a System popup that
shows which agent and which process is using it.

**Architecture:** `mods/status-plus` is a copy of Herdr's `workspace-status` with the numbers added; `lib.js` holds
every parser and sum as pure functions over recorded command output (`bun test`). `mods/system-card` is the popup
(CPU / Memory / Disk tabs); it polls while open. Ownership is the parent chain only (spec: System uses step 1), a copy
of Ports' walk.

**Tech Stack:** Herdr 0.1.15 mods (gpui-kit, gpui-base, herdr), `bun test`, macOS `ps`, `vm_stat`, `sysctl`, `df`,
`pmset`, `git`, `du`.

**Spec:** `docs/superpowers/specs/2026-11-14-ports-section-design.md` (Part 2 and "The shared piece").

## Global Constraints

- Branch `feat/ports` (Part 1 is on it; never push `main` mid-work). No `// DEBUG`, no temporary hooks in commits.
- Theme tokens; Geist / Geist Mono (`MONO`); numbers in the bar use tabular digits so they don't jitter.
- Nothing animates; re-render only when a shown (rounded) value changes.
- Named constants for every interval, threshold, size; every `exec` has a timeout; no overlapping polls.
- Thresholds (spec): CPU ≥ 80% (10 s average), pressure warn, disk < 10% free, battery < 20% → `working`; pressure
  critical, disk < 5% free, battery < 10% → `blocked`. Memory's colour follows pressure, never "used".
- Only `machine == null` terminals own processes.
- Reload after edits: `layout.switch` main, 1.5 s, emergence. Verify with `herdr-app shot` / `status`.

## Verified facts (this Mac, 2026-11-14)

- `vm_stat` first line names the page size (16384 here); lines `Pages active`, `Pages wired down`,
  `Pages occupied by compressor`. `sysctl -n hw.memsize hw.ncpu kern.memorystatus_vm_pressure_level` → three lines.
  `sysctl -n vm.swapusage` → `total = 5120.00M  used = 3709.31M  free = 1410.69M  (encrypted)`.
- `df -k ~` last line: `… 482797652 437451252 14447236 97% … /System/Volumes/Data` (KB: size, used, available).
- `pmset -g batt`: `Now drawing from 'Battery Power'` / `'AC Power'`, then `… 72%; discharging; …`.
- `ps -axo pid=,ppid=,rss=,time=,comm=`: comm last (full path, may hold spaces); `time` is `m:ss.cc` or longer.
- Each command takes ≤ 30 ms.

## Review Focus

1. The first poll has no previous sample: CPU must read "–", never 0% or a spike → Task 1 test.
2. A process that exits between two `ps` samples must not produce a negative or huge CPU → Task 1 test.
3. Many agents: By-agent rows filtered (≥ 1% CPU or ≥ 100 MB) so the 360px popup stays short → Task 2 test.
4. A missing command (Linux has no `vm_stat`/`pmset`) hides that number instead of showing 0 or an error → Task 3.
5. A remote space's terminal with a pid equal to a local one must not claim a local process → Task 2 test.

### Task 1: Parsers and CPU

**Files:** Create `mods/status-plus/lib.js`, `mods/status-plus/lib.test.js`, `mods/status-plus/fixtures.js`.

**Interfaces — Produces:**
- `parseVmStat(text) -> { page: number, active, wired, compressed } | null` (page counts).
- `memUsed(vm) -> bytes` = (active + wired + compressed) × page.
- `parseSysctl(text) -> { total: bytes, cores: number, pressure: "normal" | "warn" | "critical" }` (1 / 2 / 4).
- `parseSwap(text) -> bytes` used (the `used = 3709.31M` figure).
- `parseDf(text) -> { size: KB, free: KB }` from the last line's 2nd and 4th fields.
- `parseBattery(text) -> { onBattery: boolean, percent: number } | null`.
- `parseProcs(text) -> Map<pid, { pid, ppid, rss: KB, cpu: seconds, comm }>` (`parseCpuTime` copied from
  `mods/port-card/lib.js`).
- `cpuSample(prev: { at, procs } | null, next: { at, procs }, cores) -> { total: number /* 0–100 */,
  byPid: Map<pid, number /* % of the machine */> } | null`: per pid Δcpu ÷ (Δwall × cores) × 100, counting only pids
  in both samples whose cpu grew (≥ 0); null without `prev` or with Δwall ≤ 0.

  forms, three ps lines incl. a spaced comm).

  1/2/4 → normal/warn/critical; swap 3709.31M → bytes; df free 14447236 of 482797652; battery on/off; procs with the
  spaced comm; `cpuSample(null, …) === null` (RF1); a pid only in `next` or whose cpu dropped counts 0 (RF2);
  two cores busy for 5 s on 10 cores → total 20.

### Task 2: Sums, levels, the bar's segments

**Files:** Modify `mods/status-plus/lib.js`, `lib.test.js`.

**Interfaces — Produces:**
- `chainOwner(pid, procs, byPid) -> address | null` (walk ppid ≤ 64 hops, cycle-safe; as Ports' step 1).
- `localTerminals(terminals) -> Map<pid, address>`: shell pid and foreground pid of live terminals with
  `machine == null`, rolled up to the top-level agent (a terminal with `parent` maps to its parent's address).
- `byAgent(procs, cpu, byPid) -> { address, cpu: number, rss: KB }[]` (every process summed into its chain owner) and
  `rest` (`{ cpu, rss }` of everything else); `visibleAgents(rows) -> rows` with cpu ≥ 1 or rss ≥ 100 MB, largest first
  (RF3); `topProcs(procs, cpu, key: "cpu" | "rss", n = 8)`.
- `level(kind, value) -> "ok" | "warn" | "crit"` with the Global Constraints thresholds (cpu %, pressure, disk free
  fraction, battery %).
- `segments(state, width) -> { id, text, level }[]` for the bar: `cpu` (`34%` or `–`), `mem` (`21/36 GB`, or `21 GB`
  when narrow), `disk` (`412 GB free`), `battery` (`64%`, only on battery); dropped in the order battery, disk, memory
  total as `width` falls below `WIDE = 1100`, `MEDIUM = 900`, `NARROW = 760` (px of the status bar).
- `fmtBytes(bytes) -> "21.4 GB" | "312 MB"`.

- [ ] **Step 1: failing tests** — chain owner through a grandchild; remote terminal with the same pid ignored (RF5);
  sub-agent rolls into its parent's address; byAgent sums and `rest`; visibleAgents drops a 0.2% / 40 MB agent;
  levels at each threshold edge (79/80, 10%/9.9% free, warn/critical, 20/19, 10/9); segments at 1200 / 1000 / 800 /
  700 px.
- [ ] **Step 2:** FAIL → implement → PASS. **Step 3: commit** `feat: System sums per agent, levels and bar segments, tested`.
