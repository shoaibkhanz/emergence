# Sidebar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every worktree under its space, three sidebar sizes (open 268 / rail 48 / dots 20), and a keyboard path
into, through and out of the sidebar.

**Architecture:** Grow the blocks that exist. spaces-plus gains worktree rows (pure logic in a new `lib.js`),
folding, a focus handle with keys, and rail / dots renders. inbox gains a focus handle, keys, two-line rows and a
count badge. tabs-plus' `rail()` (⌘B) becomes the three-size toggle and `thinner` (⌘⌥B) is added.

**Tech Stack:** Herdr 0.1.15 mods (gpui-kit JS, `herdr` module), `bun test`, git CLI.

**Spec:** `docs/superpowers/specs/2026-11-13-sidebar-design.md`

## Global Constraints

- Theme tokens only (`theme()`): `t.blocked` needs you, `t.working` working, `t.done` done, `t.accent` cursor ring,
  `t.selected`, `t.hover`, `t.dim`, `t.muted`, `t.border`, `t.chrome`, `t.foreground`, `t.ansi2` ahead, `t.ansi1` behind.
- Geist 11 / 12 / 13 px, 4px grid; branch names in plain Geist (not mono); rows 28px; no always-on animation (the
  working mark is the static `mods/workspace-chrome/spinner.svg`).
- Sizes by sidebar width (`find(layout(), "sidebar").size.px`): `< 34` dots, `< 160` rail, else open. Rail 48, dots 20.
- Keys: `cmd-b` → `tabs-plus.rail` (unchanged name), new `cmd-alt-b` → `tabs-plus.thinner`, both in `layout:emergence`.
- gpui keystroke strings: `"up" "down" "left" "right" "enter" "escape" "ctrl-h" "ctrl-j" "ctrl-k" "ctrl-l"`.
- `exec(cmd, args, { cwd, on })` — args is an array; `on` is the machine (null = here).
- Nothing the sidebar does today is lost: click, right-click menu, drag to reorder, machines and Connect, Settle,
  "Working N", Settled shelf, `setAgentOrder`.
- Synthetic data only in screenshots and tests (no real names, repos, task titles). Never commit `/tmp` files.
- No synthesized OS mouse / keyboard events; drive handlers with `herdr-app do <mod>.<cmd>` and check with
  `herdr-app shot` / `herdr-app status`. Reload: `herdr-app do layout.switch --name main; sleep 1.5; herdr-app do layout.switch --name emergence`.
- Commits go on branch `sidebar`; nothing reaches `main` until the person has checked it live.

## Review Focus

- An open worktree whose path git prints differently from `rev-parse --show-toplevel` (macOS `/tmp` → `/private/tmp`,
  a symlinked home): it must not appear twice (open row and greyed row). Matched by path **or** branch (Task 1 test).
- A detached or bare worktree: a row labelled with its folder name, never "undefined" (Task 1 test).
- A remote machine that stops answering after its worktrees were listed: keep the last list, don't empty it (Task 2).
- The row under the cursor disappears (worktree removed, space closed, space folded by mouse): cursor moves to the
  nearest row above, never off the list (Task 1 test).
- Inbox cursor when a card leaves (agent settled, answered): clamped to the list, ↵ never focuses a stale agent (Task 4).

### Task 1: Worktree tree logic (`lib.js`)

**Files:**
- Create: `mods/spaces-plus/lib.js`
- Create: `mods/spaces-plus/lib.test.js`

**Interfaces:**
- Produces:
  - `parseWorktrees(text: string): {path: string, branch: string|null, bare: boolean, prunable: boolean}[]` —
    `git worktree list --porcelain` blocks; `branch` without `refs/heads/`, null when detached.
  - `parseTrack(text: string): Record<string, {ahead: number, behind: number}>` — lines of
    `git for-each-ref --format='%(refname:short) %(upstream:track)' refs/heads`; `[gone]` or none → 0 / 0.
  - `addWorktrees(rows, trees, folded: Set<string>): Row[]` — `rows`: `ordered()` output `{w, i, g, tree}`
    (`g` gains `top`); `trees`: `{[g.repo]: {list, track}}`. Returns rows with `key` added:
    space rows `{kind: "space", key: "s:" + w.id, w, i, g, tree, kids: number, parent: string|null}`,
    greyed rows `{kind: "wt", key: "p:" + JSON.stringify([on, path]), parent, on, path, label, ahead, behind}`.
    Greyed rows follow the first main space of a repo (after its nested spaces). Folded spaces keep `kids` but
    drop their child rows.
  - `nearest(keys: string[], old: string[], cur: string|null): string|null` — the cursor after a refresh: `cur` if
    still in `keys`, else the closest key that came before it in `old` and is still in `keys`, else `keys[0]`.
